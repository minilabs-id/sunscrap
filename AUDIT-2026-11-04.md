## 1. Ringkasan eksekutif

Fundament aplikasi kuat: SQL terparameterisasi di mana-mana, transaksi `BEGIN IMMEDIATE`, claim/lock/reclaim yang benar, escaping HTML konsisten, allowlist host untuk scraper, CSP ketat tanpa inline handler, worker tersembunyi ter-sandbox, cache tanpa navigasi. Sejak audit v1, **semua P0 yang dapat diverifikasi sudah benar-benar tertutup**, dan perbaikan v2 (commit `2eb71c8`) menutup 4 bug nyata lagi (parseUtc zona, sentinel 1<<40, `is_new` inflasi, komentar null).

**Sisa pekerjaan nyata:**
1. **P0 tunggal tersisa di kode:** `loadURL()` tanpa timeout — worker bisa menggantung selamanya (F-05 "selesai" hanya di lapisan `executeJavaScript`).
2. **UI/UX:** query berat per keystroke (intel full-recompute), nol loading state/aksesibilitas keyboard, export bisa mengekspor **semua** diam-diam, aksi destruktif tanpa gesekan, `catch {}` senyap di mana-mana.
3. **Proses & kejujuran produk:** README tidak jujur soal ToS/legalitas; dokumen strategi ter-commit; tidak ada LICENSE/CI/lint; dua dokumen besar yang saling bertentangan dan usang.

## 3. Koreksi terhadap analisis sebelumnya (penting — jangan diikuti mentah-mentah)

**B.1.2 `verifiedFilter` "skip-verified gagal massal" — TIDAK REPRODUCE.** Dokumen `OPSI-TERBAIK.md` mengklaim task PROFILE membuat `MAX(v2.id)` menunjuk PROFILE sehingga semua yang sudah OK di-enqueue ulang. Faktanya task PROFILE **tidak punya `target_id`** (`INSERT ... kind='PROFILE'` tanpa kolom `target_id`), dan subquery `MAX` dicakup `WHERE v2.target_id = v.target_id` — PROFILE tidak pernah ikut. Direproduksi langsung di DB `:memory:`: setelah POST OK + satu kunjungan profil, `enqueueRun(full=false)` → `created: 0, skipped_verified: 1` — perilaku benar. Klausul "tanpa scope audit" juga mustahil (target_id menentukan audit). Saran "tambah `kind='POST'`" tidak berbahaya tapi **tidak perlu**; item ini bukan bug P1 dan sebaiknya dicoret agar tidak membuang waktu.

**B.1.1 claim tanpa fencing token — premisnya lemah untuk arsitektur ini.** Double-claim menuntut dua worker mengklaim task yang sama; aplikasi ini single-instance (`requestSingleInstanceLock`) dan single-loop dengan guard `state.busy` (`worker.js`), jadi dua klaim bersamaan tidak terjadi dalam satu proses. Setelah crash, task dipulihkan oleh `reclaimExpired` — prosesnya sudah mati, tidak ada "hasil terlambat". Yang **nyata** dan harus diperbaiki:
1. `worker.js:212` — `db.updateTaskResult()` return `false` **diabaikan** → hasil scrape hangus tanpa log/notify (kehilangan data senyap).
2. `scraper.js` — `load()` (navigasi) **tanpa timeout**, padahal `executeJavaScript` sudah dibatasi 45 dtk → satu halaman menggantung (challenge IG, koneksi putus) membekukan worker **selamanya**; reclaim tidak pernah tercapai karena loop tidak pernah sampai ke klaim berikutnya. Inilah P0 yang sesungguhnya.
3. `render-process-gone` (`scraper.js:78-82`) tidak menolak promise yang sedang `await` — tertahan sampai timeout (atau selamanya untuk `loadURL`).

Fence token tetap murah untuk kebersihan, tapi salah prioritas bila dikerjakan sebelum (1) dan (2).

## 4. Temuan kode & arsitektur — masih terbuka

**A. [P0] `loadURL` tanpa timeout** (`scraper.js:103`). F-05 hanya tuntas di lapisan JS. Fix minimal:
`withTimeout(win.loadURL(url), 30_000, 'LOAD_TIMEOUT')` → `destroy()` window → task `FAILED/TRANSIENT`; tambah `webContents.on('unresponsive', …)` → destroy + log. Jangan pakai ulang window setelah timeout/crash; 2 crash/jam → hentikan worker.

**B. [P1] Index `tasks(target_id, id)` belum dibuat.** Semua window `PARTITION BY target_id` (`getTargets`, `getSummary`, `getLatest`, `getExportRows`, `retryFailedTargets`) scan/sort penuh; tanpa index `idx_tasks_target ON tasks(target_id, id)` SQLite memakai temp b-tree. 5 menit, dampak besar. (`getTargets` juga menghitung CTE berat **dua kali**: `COUNT(*)` + halaman — satukan dengan `COUNT(*) OVER () AS total_count`.)

**C. [P1] Cadangan tidak pernah diverifikasi.** Setelah VACUUM sukses, tidak ada `PRAGMA integrity_check` pada hasil / banding `COUNT(*)` per tabel vs sumber. Untuk alat "bukti" sengketa, backup tanpa verifikasi = rasa aman palsu. Tambahkan: buka hasil read-only + `integrity_check` + bandingkan jumlah baris (atau minimal `VACUUM` + spot-check).

**D. [P1] `enqueueProfileVisits` masih me-reset `needs_visit=1` untuk SEMUA akun** (`db.js`, fungsi `enqueueProfileVisits`) — efek lintas audit tetap ada (v1 D-06). Batasi `UPDATE` ke username yang muncul di `targets` audit tersebut.

**E. [P2] Export menjalankan query berat dua kali** — handler `data:export` memanggil `getExportRows()` untuk cek kosong, lalu `writeExport()` memanggil lagi (`ipc.js`). Ganti pre-check dengan `COUNT(*)` saja.

**F. [P2] `params.offset` tidak dijepit** — `Math.max(0, Number(params.offset))` → `NaN` bila input `"abc"` (`getTargets`, `getAccountIntel`) → ter-bind ke SQLite → error IPC mentah; tab Target bisa blank. Pakai `clampLimit` seperti `limit`.

**G. [P2] `getCompare` masih menghitung target tanpa snapshot sebagai "posts"** (`LEFT JOIN latest` tanpa cek metrik) — inflasi angka di laporan klien. Lewati baris tanpa ≥1 metrik.

**H. [P2] Kode mati & aroma:** `getDashboardStats()` (read-path memutasi DB; hanya dipakai tes) — hapus atau dimurnikan; `getTargetWithAudit`, `getAccountProfile` — tidak dipanggil mana pun; parameter `cursorless` di `cachedTargetCounts`; `siblings.sort((a,b) => -(a.score||0) + (b.score||0))` (benar tapi menipu — tulis `(b.score||0) - (a.score||0)`); `searchData` `LIKE` tanpa `ESCAPE '\'` + escape input; `getAudit()` = full `getAudits().find()` (5 subquery + `cachedTargetCounts` correlated `rtrim/substr` non-sargable setiap panggilan) — tulis query khusus 1 audit; `getAccountIntel()` full-recompute per refresh — materialisasi / TTL + generasi invalidation.

**I. [P2] `getQueueStats()` menghitung OK/FAILED seumur hidup** — angka KPI di tab Proses adalah total historis, bukan antrean sekarang; label mengecoh keputusan operator (lihat juga UI U-11).

**J. [P3] Dua format waktu campur** (`"YYYY-MM-DD HH:MM:SS"` vs ISO `Z`) — perbandingan string "kebetulan benar"; standardisasi ISO-Z untuk kolom baru; pertahankan legacy dengan normalisasi. `sqlite_sequence` sudah direset di `clearAll` ✅. FK diaktifkan tapi **nol REFERENCES** di DDL.

**K. [P3] Tidak ada migrasi skema nyata** — `SCHEMA_VERSION = 5` ditulis ke `PRAGMA user_version`, tak pernah dibaca; evolusi skema hanya `CREATE TABLE IF NOT EXISTS`. Runner `MIGRATIONS[6..]` + tes upgrade v5→v6 wajib sebelum v1.1 menyentuh skema.

### 5.0 Skor per area

| Area | Nilai | Inti |
|---|---|---|
| Visual language & konsistensi | B+ | Token, spacing, radius, shadow konsisten; profesional |
| Alur inti (import → worker → review) | B− | Worker-first, tapi tanpa onboarding/estimasi biaya |
| Aksesibilitas (keyboard/SR) | **D** | Nav tak fokus; tanpa focus-visible; modal tanpa role; toast tanpa aria-live |
| Umpan balik & error | **D** | `catch {}` senyap; tanpa spinner/skeleton |
| Performa persepsi | C− | Query berat per keystroke; select dibangun ulang saat polling |
| Kontras WCAG | C | 3 warna teks gagal AA (terukur, §5.4) |

| Docs vs UI | C | README "+ Audit baru" vs UI "+ Import data"; "32 tes" |

### 5.1 Temuan kritis

**U-01. Ketik 1 huruf = 1 full-recompute DB.** `#target-q` & `#account-q` terikat `input` → `loadTargets()`/`loadAccounts()` **tanpa debounce** (`app.js`). `loadAccounts` memanggil `getAccountIntel()` = muat seluruh `accounts` + `account_posts` + `account_history` + `targets` + pairing kontak/template/serentak + union-find — **setiap keystroke**; "budi" = 4 recompute penuh, UI macet, dan respons usang bisa menimpa yang baru (tak ada sequence guard). **Fix:** debounce 250–300 ms + abaikan respons usang (counter `reqId`); filter client-side sampai jeda.

**U-02. Aksesibilitas keyboard & screen reader nihil.**
- `.nav-link` = `<a>` **tanpa `href`/`tabindex`/`role`** (`index.html`) → tak bisa difokus/dioperasikan; seharusnya `<button>` (atau pattern `tablist`+`aria-selected`+`aria-controls`).
- Baris tabel/`.row-item.clickable` tidak fokus; perlu `tabindex="0"` + aktivasi Enter/Space.
- **Tidak ada `:focus-visible`** untuk tombol/nav/baris/checkbox — hanya `.input:focus`/`.select:focus` yang bergaya.
- Checkbox `.sel` tanpa `aria-label` → SR hanya membaca "kotak centang".
- Modal: tanpa `role="dialog" aria-modal="true"`, fokus awal, trap Tab, restore fokus ke pemicu; konten belakang tak `inert`.
- Toast tanpa `role="status" aria-live="polite"` → pengguna tunanetra tak tahu impor berhasil/gagal.

**U-03. Kegagalan senyap merusak kepercayaan.** Hampir semua `load*` ditutup `catch {}`: `loadRiskAccounts`, `loadProcess` (Proses kosong tanpa pesan), `refreshDashboard`, `loadSettings`, `openTarget`/`openAccount` — modal tidak terbuka pun tanpa sepatah umpan balik. **Fix:** pola `try/catch` → `toast(msg, 'error')` + log; tab Proses tampilkan banner "Gagal memuat — coba lagi" dengan tombol retry.

**U-04. Export bisa mengekspor SEMUA diam-diam.** `#btn-export` hanya memetakan `partial→PARTIAL`, `failed→FAILED`, `ok→OK`; filter **"Selesai (done)"** (OK+PARTIAL) dan lainnya jatuh ke `undefined` → `getExportRows(null)` = **seluruh snapshot** diekspor tanpa konfirmasi lingkup. **Fix:** peta eksplisit (`done` → dua query atau `status IN ('OK','PARTIAL')`), modal konfirmasi *"Export N baris · audit X · status Y"*, tombol nonaktif bila filter tak terpetakan. Ekspor data klien — jangan pernah mengejutkan pengguna.

**U-05. Aksi destruktif tanpa gesekan.**
- "Hapus semua data": 1 klik + modal, **tanpa ketik `HAPUS` & tanpa opsi cadangkan dulu** — tidak bisa dibatalkan.
- "Hapus sesi login (IG & TikTok)": 1 klik tanpa konfirmasi; memutus sesi worker yang berjalan.
- "Hapus audit": tidak menampilkan dampak ("beserta N target, M snapshot").
- `before-quit` tanpa timeout — shutdown bisa menggantung; tambahkan `Promise.race(5s)`.

**U-06. `<webview>` bebas navigasi di sesi login; `file://` semua lolos.** Tab Browser memuat **URL arbitrer** di partisi `persist:sunscraping` yang berisi sesi IG/TikTok — aplikasi de-facto browser umum; bertentangan dengan klaim README "allowlist host"; risiko phishing di dalam chrome tepercaya. `will-navigate` meloloskan **semua** `file://` — dokumen lokal mewarisi preload (`window.sunscraping` penuh: delete/clear-all). **Fix:** allowlist navigasi webview ke `instagram.com`/`tiktok.com` (+subdomain) di `browserNavigate` **dan** `will-attach-webview` (atau partisi `persist:browser` tanpa sesi); `will-navigate` izinkan hanya path persis `renderer/index.html`; tombol "Buka di browser luar" untuk sisanya.

**U-07. State basi setelah hapus.** `state.auditId` dipertahankan walau audit sudah dihapus; `loadAudits()` menampilkan "Semua audit" tapi `state.auditId` tetap menunjuk id mati → export/retry/target bekerja pada audit hantu. **Fix:** `state.auditId = null` bila id hilang dari daftar; samakan value `<select>`.

### 5.2 Temuan menengah

- **U-08. `#global-audit` dibangun ulang saat polling** — `innerHTML` ditulis di tiap event `data`; dropdown terbuka bisa kehilangan fokus/opsi. Diff dulu (tulis bila daftar id berubah) atau jangan rebuild saat `document.activeElement === select`.
- **U-09. Tab non-Dashboard tak ikut refresh** — polling hanya Dashboard/Worker; tab Target/Akun/Proses basi selama worker berjalan → kesan "macet". Refresh tab aktif (debounced) atau badge "data berubah".
- **U-10. Jendela dashboard ganda** — tray "Buka dashboard", `activate`, `second-instance` semua `createMainWindow()`; tidak reuse/focus.
- **U-11. "OK / Gagal" di Proses = total seumur hidup** — `getQueueStats()` menghitung seluruh riwayat; KPI tak bermakna untuk "antrean sekarang". Tampilkan Menunggu/Berjalan (aktual) + rasio sukses sesi + **banner "Login diperlukan"** dengan tombol langsung ke `openLogin()` saat AUTH error beruntun (kasus macet paling umum, paling tidak terbantu).
- **U-12. Tanpa ETA di UI** — estimasi "sisa ~X" hanya di log; tampilkan "Sisa antrean ~N menit (perkiraan)" di Proses.
- **U-13. First-run kosong tanpa panduan** — Dashboard semua nol + "Belum ada data."; tak ada checklist *Login → Import → Mulai worker*; tambah onboarding 3 langkah + CTA.
- **U-14. Halaman Akun terpotong di 200 tanpa pager** — >200 akun → sisanya tak terlihat (yang paling "penting" malah terpotong). Pager seperti Target.
- **U-15. Opsi filter "Curiga" menyesatkan** — `score ≥ 6`, superset dari "Pola ternak"; hasil tumpang tindih & label menghakimi. Hapus, atau jadikan window `2 ≤ score < 6`.
- **U-16. Tanggal tidak dilokalkan** — `scraped_at.slice(0,16)` mentah "2026-11-04T21:16"; pakai `Intl.DateTimeFormat('id-ID')`.
- **U-17. Tidak ada `@media print`** — Ctrl+P mencetak sidebar+toolbar; sembunyikan chrome, untuk "alat bukti" cetak/PDF adalah jalan laporan wajar.
- **U-18. `prefers-reduced-motion` tidak ditangani** (`transition: background 120ms`) — hormati preferensi.
- **U-19. Link eksternal tanpa affordance** — `<a>` di tabel terbuka via `will-navigate` → browser luar (benar), tapi tanpa ikon/title "buka di browser"; tambah ikon ↗ + `title`.
- **U-20. Menu tray "Buka dashboard"** tidak fokus-if-exists (U-10); doble-klik tray → banyak jendela.
- **U-21. Konsistensi salinan** — README "+ Audit baru" vs UI "+ Import data"; teks bantuan/tooltip tidak ada di UI sama sekali.

### 5.3 Kritik kualitatif (desain)

1. **Visual rapi, tapi menakutkan bagi novice & menyesatkan bagi expert.** Semua angka besar tanpa konteks/aksi — alat ini menuntut *keputusan*, tapi tak pernah menjawab "apa yang harus saya lakukan selanjutnya?". Setiap layar butuh satu baris "langkah berikutnya".
2. **Worker tanpa ring fence.** Tidak ada disabled-state "Login IG dulu", estimasi biaya kunjungan, atau mode monitor/preview; operator mengklik "Mulai worker" lalu berharap.
3. **Kegagalan = bisikan.** Error muncul 4 detik lalu hilang; tidak ada riwayat/badge notifikasi. Di bawah jaringan buruk, operator tidak pernah tahu impor/scrape gagal.
4. **Semua panel bobot sama** — tidak ada hierarki "Perlu tindakan → Ringkasan kampanye → Detail"; Dashboard datar.
5. **"Alat bukti" tanpa bukti yang bisa dilihat** — detail target hanya angka; link post melempar ke browser tanpa konteks; tak ada screenshot/“lihat bukti”/“salin link bukti”. Untuk sengketa klien ini lemah.
6. **Ekspor Excel satu-satunya jalan keluar** — tambah "Salin ke clipboard (tab-delimited)" untuk tempel cepat ke email/WA.
7. **Kredit tempatnya benar (pertahankan):** `tabular-nums`, sticky header, `max-height`, radius/shadow konsisten, locale id-ID, empty-state manusiawi, Esc menutup modal, danger = merah solid, preload minimal.

## 6. Kritik proses, etika & kejujuran produk

1. **README tidak jujur soal legalitas.** Ia menulis "patuhi ToS masing-masing platform" sambil seluruh nilai jualnya: menghindari deteksi anti-bot, tanpa API, biaya nol. IG/TikTok melarang akses otomatis; pacing/budget/session-break **mengurangi pemblokiran, bukan mengubah status legalnya**. README seharusnya: "Scraping data publik tanpa API; **melanggar ToS**; gunakan akun khusus; risiko pemblokiran/banned sepenuhnya pengguna; data publik ≠ bebas diproses”. Klaim "allowlist host cocok persis" juga bertentangan dengan tab Browser (§5 U-06).
2. **Privasi & UU PDP 27/2022.** Fitur "kontak bio sama" membanding nomor HP/email dari bio ribuan akun **tanpa dasar yang terdokumentasi**; label "Pola ternak / Pola kembar" ditampilkan ke klien atas orang nyata. Minimal: DPIA-lite, jalur hapus-per-permintaan (data akun + bio), label netral ("Indikasi keterkaitan — rendah/sedang/kuat") + human review, disclaimer di export. Ini fitur wajib, bukan catatan kaki.
