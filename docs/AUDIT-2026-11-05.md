## 3. Temuan terbuka

### P1 — dampak harian (kepercayaan/efisiensi operator)

1. **Baris tabel tidak bisa dioperasikan keyboard.** `tr.clickable` (Target `renderer/app.js`, Akun) dan kartu
   risiko hanya punya listener `click`; tanpa `tabindex`/`role`/handler Enter/Space; `.clickable` tanpa gaya
   `:focus` (`renderer/styles.css`). Pengguna keyboard-only terhalang.
2. **Gagal baca = diam di 3 tempat.** `loadRiskAccounts`, `loadProcess`, `loadSettings` memakai `catch {}` →
   panel basi tanpa notifikasi (Target/Akun sudah pakai toast).
3. **Tanpa busy-state pada aksi async mahal.** Export, Backup, Restore, Rerun/Retry, Hapus-sesi/semua bisa
   diklik 2× → dialog/aksi dobel.
4. **Status `running` tak dibedakan dari `pending`** (`styles.css` memakai warna `--faint` yang sama).
5. **Empty state tanpa CTA** — "Tidak ada target/Akun/aktivitas" berhenti di teks tanpa tombol ke aksi.

### P2 — arsitektur/kebenaran

6. **Dead code diekspor:** `db.getDashboardStats`, `db.getTargetWithAudit`, `db.getAccountProfile` tidak dipakai
   IPC/renderer (hanya tes). `getDashboardStats` memicu `reclaimExpired()` (tulis) bila kelak dipanggil.
7. **Jalur "audit inkremental" dorman.** `enqueueRun(full=false)` ada, tetapi tombol "Audit ulang" selalu
   `full=true` → setiap rerun men-scrape ulang semua target.
8. **`withTimeout` tidak membatalkan promise yang kalah** → pekerjaan isolated-world bisa tetap jalan setelah timeout.
9. **Task `PROFILE` selalu diprioritaskan** di atas POST → batch kunjungan profil besar bisa membuat post kelaparan.
10. **`getQueueStats` tak mereclaim task `RUNNING` basi** → angka Menunggu/Berjalan bisa termasuk task kedaluwarsa.
11. **Jalur panas `getTargets`** memakai `ROW_NUMBER() OVER (PARTITION BY target_id)` **tanpa filter audit** → berat di DB besar.
12. **Export memuat baris dua kali** (`ipc.js` lalu `export.js`).
13. **`snapshots` tanpa retensi** — tumbuh tanpa batas; export selalu seluruh histori.
14. **`retryFailedTargets`/`retryTargets` memotong 200 id** tanpa memberi tahu bila terpotong.

### P3 — kosmetik / dokumentasi

15. **Dua sumber kebenaran versi:** `SCHEMA_VERSION` (db.js) vs hardcode `5`/`v1.0.0` di renderer; `APP_VERSION` (kini dari `package.json`).
16. `README` arsitektur sempat tidak menyebut `avatar.js`/`updater.js`; `scripts/monitor.js` ada typo "kometar".
17. `build/icon.png` == `assets/icon.png` (duplikat; dibutuhkan electron-builder).
18. Dokumen audit lama tersimpan di repo (sudah dikonsolidasikan ke `docs/`).

## 4. Yang sudah benar (pertahankan)

SQL 100% parameterized; transaksi `BEGIN IMMEDIATE` + WAL; allowlist host dua lapis; sandbox/contextIsolation;
CSP ketat tanpa remote script; `esc()` konsisten; sanitasi formula export; avatar lokal ber-allowlist + magic
bytes + cap; restore temp-then-swap + guard skema; storage tmp+rename atomik; single-instance lock + tray-first;
pemisahan modul murni yang teruji.
